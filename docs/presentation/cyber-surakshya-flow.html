Cyber Surakshya · architecture schematics

How a packet becomes
a blocked IP

Every path through the platform, from the CICIDS2017 CSV that trains the model to the containment action the ResponseAgent refuses to take without an analyst. Nine schematics, drawn from the code as it stands on branch surya.

7 attack classes 6 agents 42 model features 3 ingress paths 40 HTTP endpoints 1 served model — model_DNN.pkl
Reading the schematics

Three tracks, colour-coded throughout

Runtime

Runs on every request. The agent pipeline, the API layer, the live capture worker.

Build time

Run by hand, never at request time. Training, artifact generation, attack profiles.

Enforcement

Gates that can refuse. Approval checks, the ActionGuard, trust tiers, error exits.

Storage

Anything that outlives a request: pickled artifacts, Redis streams, Qdrant + SQLite.

Schematic 01 · the whole system

Master map

The build-time track on the left produces artifacts that the runtime track loads exactly once, at server boot. Nothing in the runtime track ever reads the dataset or retrains — a fact worth holding onto, because it means every model change requires a deliberate offline run and a server restart.

The selection gate is drawn as enforcement because it can reject every model that scores well on the wrong metric.

Why the selection gate matters: RandomForest, GradientBoosting and the VotingEnsemble all score above 0.99 weighted F1 while catching 8–10% of WEBATTACK. Selecting on weighted F1 would promote one of them. The floor at 50% per-class recall is what keeps the DNN in production.

Schematic 03 · runtime ingress

Schematic 04 · orchestration

The coordinator loop

The graph is a hub and spoke, not a chain. Every worker node returns to the coordinator, which re-derives the work queue from state and picks the next stage. This is what lets a single run drain N events — before the coordinator existed, a run processed exactly one event and silently dropped the rest, because each agent handles one pending item per call.

The memo lives in state metadata, not on the agent instance — agents are shared singletons across threads.

Stall detection is the anti-livelock guarantee. Agents swallow their own exceptions and return without producing a result. A naive "route while work is pending" loop would dispatch to a broken stage forever; instead the stage is excluded and the reason is recorded as a run anomaly.

Schematic 05 · the four pipeline stages

What each agent turns into what

STAGE 01

DetectionAgent

Takes the first undetected SecurityEvent, scores it through the IDS adapter, emits a DetectionResult with label, confidence, risk score and severity.

agents/detection/detection_agent.py
STAGE 02

AnalysisAgent

Takes the first unanalysed detection, runs the DeterministicRuleEngine, emits evidence, a plain-language summary, reasoning and explicit uncertainty flags.

agents/analysis/analysis_agent.py
STAGE 03

DecisionAgent

Takes the first undecided analysis, matches it against policy rules, and emits an action, a priority, a rationale, and whether a human must approve it.

agents/decision/decision_agent.py
STAGE 04

ResponseAgent

Takes the first unresponded decision through the approval gate, the ActionGuard and the trust policy, then executes — or refuses, and says why.

agents/response/response_agent.py

Every agent follows the same LangGraph node contract — __call__(state) -> state — and appends to an operator.add-reduced list. Nodes return only their additions, never the whole state.

Schematic 06 · inside detection

Supervised classifier plus a second opinion

The classifier answers "which of the seven classes is this". The anomaly layer, trained on benign traffic only, answers a different question: "have I seen traffic shaped like this before". When the classifier says BENIGN and the anomaly layer disagrees, the detection is downgraded to INCONCLUSIVE rather than dismissed.

Schematic 07 · enforcement

Four gates before anything is executed

This is the only part of the platform that acts on the outside world, so it is the only part built to refuse. A decision passes through a rejection check, a decision-level approval gate, the ActionGuard, and an idempotency check — and each refusal is recorded as a ResponseResult with the verdict, the rule that fired, and the reason.

Schematic 09 · the outer loop

Learning runs over history, not over flows

The LearningAgent is deliberately not a pipeline node — as one it would re-derive platform-wide metrics on every single flow. It reads the memory collections on demand, and it recommends without executing. Its accuracy figures depend entirely on analyst feedback, because the platform cannot detect its own false positives by introspection.

Reference · where things live

Four kinds of state, four lifetimes

StoreLifetimeHoldsSurvives restart
PlatformSharedStateone graph runevents, detections, analyses, decisions, responses, errors, coordinator memono
PlatformRuntimeprocessmodel artifacts, graph runtime, attack profiles, servicesno
Qdrant + SQLiteon diskevery agent result, approvals, feedback, learning reportsyes
Redis streamboundednormalized flows in transit from capture to pipelineyes, until trimmed

The manifest is the contract. artifacts/manifest.json names the served model, the selection rule that chose it, the dataset fingerprint and the library versions — so which model is in production is an auditable choice rather than a side effect of file ordering on disk.
